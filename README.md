# Hotel OS

**Універсальна система управління готелем для незалежних готелів.** Один вхід замість п'яти розрізнених інструментів (таблиці, месенджери, кабінети OTA, паперовий календар) для керування бронюваннями, гостями, оплатами, прибиранням та комунікацією.

Цей репозиторій — це **статичне демо продукту / прототип для інвесторів**: повністю клікабельна, тільки фронтенд-версія продукту, розгорнута на GitHub Pages за адресою `hotelos.webart.work`.

## Проблема

Незалежні готелі та гостьові будинки (орієнтовно 5–50 номерів) зазвичай працюють одночасно з:

- паперовим або табличним календарем для контролю зайнятості номерів
- Instagram/Telegram/телефоном для спілкування з гостями
- Booking.com або подібними OTA як єдиним каналом продажів
- ручним, схильним до помилок обліком оплат, передоплат і повернень
- відсутністю спільної системи для власника, рецепції та прибирання

Це повільно, призводить до помилок (подвійні бронювання, пропущені оплати, відсутність CRM) і тримає готель залежним від комісій OTA замість побудови прямих відносин із гостями.

## Продукт

Hotel OS замінює все це однією системою, побудованою навколо простої ідеї: **Номери → Дати → Бронювання**, доступною потрібній людині з потрібним рівнем доступу:

- **Календар і бронювання** — одна сітка для всіх номерів і дат, перетягування, контроль конфліктів, швидке або повне створення бронювання
- **CRM гостей** — кожен гість автоматично отримує профіль: історія проживань, витрати, побажання, визначення постійних гостей
- **Оплати** — передоплати, залишки, повернення та чітке розділення "фактично отримані кошти" й "вартість бронювання"
- **Прибирання** — дошка готовності номерів із пріоритетами, щоб жоден номер не залишався непідготовленим до заїзду
- **Повідомлення** — єдина скринька для всієї комунікації з гостями, з шаблонами та допомогою AI у написанні
- **Автоматизації** — правила звичайною мовою ("за 24 години до заїзду → надіслати інструкцію") замість складного конструктора workflow
- **Аналітика продажів** — звідки насправді приходять бронювання та дохід (прямі / OTA / соцмережі), щоб показати готелям цінність власних відносин із гостем
- **Hotel AI** — помічник, що враховує роль користувача та відповідає на операційні питання ("хто ще не оплатив?", "які номери вільні на вихідні?") звичайною мовою, використовуючи лише дані цього готелю
- **Сторінка прямого бронювання** — публічна сторінка бронювання для кожного готелю (посилання для Instagram bio, Google Business, QR-коду), щоб гості бронювали напряму, без комісії OTA
- **Команда та ролі** — Власник / Менеджер / Рецепція / Прибирання — кожен бачить лише те, що потрібно для його ролі

## Бізнес-модель

SaaS-підписка, оплата за готель, тарифікація за кількістю номерів (ціни показані на головній сторінці):

| Тариф | Номерів | Ціна | Що входить |
|---|---|---|---|
| Start | до 10 | €19/міс | Календар, бронювання, CRM гостей, оплати, прибирання, пряме бронювання |
| Small (рекомендований) | до 25 | €39/міс | + Автоматизації, аналітика продажів, AI-помічник |
| Hotel | до 50 | €69/міс | + Більше працівників, розширені автоматизації, пріоритетна підтримка |

Сторінка прямого бронювання — це свідомий важіль зростання: вона дає готелям привід переводити гостей з OTA на прямі канали, якими вони самі керують, а сторінка "Продажі" покликана зробити це наочним ("34% бронювань цього місяця прямі, порівняно з 31% минулого місяця").

## Статус: цей репозиторій — дизайн-прототип, а не продукт

Усе тут — це **статичні HTML/CSS/JS без бекенду, бази даних та автентифікації** — прості файли, без збірки. Мета — продемонструвати повний досвід продукту (UX, сценарії, структуру інформації) до інвестицій у реальну розробку. Конкретно:

- Усі дані захардкоджені окремо для кожної сторінки й скидаються після перезавантаження — нічого не зберігається і не передається між сторінками
- Вхід, оплати, повідомлення та відповіді AI повністю симулюються на клієнті
- Там, де насправді потрібна інтеграція (платіжні провайдери, доставка email/SMS, реальна автентифікація), інтерфейс прямо про це повідомляє, а не імітує це

## Карта сторінок

- `/` — маркетингова головна сторінка (тарифи, можливості, тизер AI)
- `/login/` — демо автентифікації (вхід, запрошення, відновлення пароля, ролі) — усі стани доступні через демо-перемикач на сторінці, без реального бекенду
- `/dashboard/` — щоденний операційний огляд (заїзди/виїзди сьогодні, завантаження, AI-інсайт)
- `/calendar/` — сітка бронювань номер × дата
- `/booking/` — сторінка деталей одного бронювання
- `/new-booking/` — повна форма нового бронювання (дати → номер → гість → оплата)
- `/guest/`, `/guests/` — профіль окремого гостя та повний список CRM
- `/rooms/` — номерний фонд і статуси
- `/payments/` — оплати, передоплати, повернення
- `/housekeeping/` — дошка готовності номерів для персоналу
- `/messages/` — скринька комунікації з гостями
- `/automations/` — правила автоматизацій звичайною мовою
- `/sales/` — аналітика джерел бронювань і доходу
- `/ai/` — AI-помічник Hotel AI
- `/team/` — управління персоналом та ролями
- `/settings/` — налаштування готелю
- `/book/` — публічна сторінка прямого бронювання для гостей (дати → номер → оплата → підтвердження)
- `/confirmation/` — сторінка підтвердження бронювання для гостя
- `robots.txt`, `sitemap.xml` — налаштування SEO/індексації
- `CNAME` — власний домен для GitHub Pages
