# gemini-gem/: службові нотатки (не завантажувати в Gem)

Ця папка містить конфігурацію Gemini Gem «Hotel OS Помічник», довідкового бота для персоналу
готелю. Сам README не завантажується в Gem.

## Що куди вставляти в Gem

- `description.md` → поле **Description** (ліміт 300 символів).
- `instructions.md` → поле **Instructions**.
- `pages/*.md` → **Knowledge files** (ліміт Gemini Gems: 10 файлів, зараз 9, є один запас).

## Файли знань

| Файл | Що описує |
| --- | --- |
| `overview-login.md` | Головна (/), вхід (/login) через «Тестовий вхід», спільна навігація CRM |
| `roles-access.md` | 7 ролей, домашні сторінки, хто бачить які розділи, хто може які дії |
| `dashboard-calendar.md` | Огляд, Календар |
| `rooms-housekeeping.md` | Номери, Прибирання |
| `guests-messages.md` | Гості, Повідомлення |
| `payments-sales.md` | Оплати, Продажі |
| `ai-automations.md` | Вбудований AI-помічник, Автоматизації |
| `team-settings.md` | Команда, Налаштування |
| `not-available.md` | Сторінки та функції, яких ще немає (щоб бот не давав мертвих посилань) |

Кожен розділ сторінки має структуру: `### Призначення` / `### Хто має доступ` /
`### Що можна робити` / `### Обмеження` / `### Посилання`.

## Джерела правди

- **Функціонал сторінок** береться з реальних Angular-компонентів `src/app/pages/<page>/`
  (`.component.html` + `.component.ts`), а не зі старих `_source/` HTML.
- **Ролі та права** береться з `CRM.md` у корені репозиторію. Якщо CRM.md змінився, онови
  `roles-access.md` і підрозділи «Хто має доступ».
- Якщо код поводиться інакше, ніж вимагає CRM.md, файли знань описують **фактичну поведінку**
  (з приміткою в «Обмеженнях»), а розбіжність записується в `CRM.md` → Implementation gaps.

## Посилання та якорі

Angular-версія не має `id`-якорів на секціях CRM-сторінок, тому посилання ведуть на саму
сторінку (`https://hotelos.webart.work/payments`). Робочі якорі є лише:
- на головній: `#product #features #calendar #crm #booking #payments #housekeeping #messages
  #sales #ai #hotels #pricing`;
- у Налаштуваннях: хеші з `HASH_TO_SECTION` у `settings.component.ts`.

Сторінки CRM без обраної ролі перенаправляють на /login, тому бот підказує шлях
«Вхід → екран «Тестовий вхід» → роль».

## Коли оновлювати

Після змін у сторінках, ролях чи правах (див. правило 3 у `CRM.md`) перевір відповідний файл
у `pages/`. Автоматичної синхронізації немає.

Останнє повне оновлення: 23 вересня 2026, під Angular-версію з рольовим доступом.
